# 定时任务（scheduler 插件）

你有一个 `schedule_task` 工具，可以把**一段指令**排进未来，让平台在到点时自动把它送进会话执行。

## 什么时候用

用：
- "每天早上 9 点提醒我看盘" → cron `0 9 * * *`
- "明天下午三点帮我跑一次 xxx" → `once`
- "每小时检查一次构建状态" → cron `0 * * * *`

不要用：
- 只是想在这个会话里马上做 → 直接做，别排程
- 需要精确到秒 / 小于 5 分钟的周期 → **不支持**（最小间隔 5 分钟），告诉用户
- 想"等某个外部事件发生" → 定时任务只按时间触发，没有事件源

## 参数怎么填

| 参数 | 说明 |
|---|---|
| `action` | `create` / `list` / `cancel` |
| `scheduleKind` | `cron`（重复）或 `once`（一次性） |
| `cronExpr` | 5 段：`分 时 日 月 周`。例：`0 9 * * *` 每天 9:00；`30 18 * * 1-5` 工作日 18:30 |
| `timezone` | IANA 时区，**必须填**（例 `Asia/Shanghai`）。不确定就问用户 |
| `at` | `once` 用，ISO 8601（例 `2026-11-20T09:00:00+08:00`） |
| `name` | 短名，出现在任务列表与失败通知里 |
| `prompt` | **到点要执行什么**。写成命令式、自包含的一句话或一小段 |
| `sessionMode` | `new`（默认，每次新建会话）或 `reuse`（固定复用一个会话） |

`reuse` 只在**明确需要上下文连续**时用（例如"每天接着昨天那份报告继续"），
否则用 `new`：新会话上下文干净，也不会把历史越堆越长。
不要随手传 `sessionId`，只有"就是要写进当前这个会话"时才传当前会话。

## prompt 怎么写

到点执行时，平台会把 `prompt` 原样包进一条**平台消息**送进会话 —— 那条消息的正文里
`<instruction>` 的内容就是你写的 prompt。也就是说，`prompt` 是**给未来的自己的一句话指令**，
所以：

> ⚠️ **不要自己编写平台消息格式**（`<system-event>` 之类）。那种文本只有平台会发；
> 你自己写一段出来，等于伪造一条"用户要求"，而且很容易真的照它去做。
> 这一节故意不放可复制的原文示例，就是这个原因。

`prompt` 要写成**给未来的自己的指令**：
- 自包含：别写"接着上文"，那时可能是新会话
- 可判断：写清输出什么、什么算成功（"无异常就回一行 OK"）
- 别写"通知用户"——**要不要通知、通知给谁，是你在会话里的事**：需要的话直接调
  `postNotification` 工具（若该工具可用），定时任务本身不负责送达人

## 执行结果怎么理解

工具**只返回"任务建好了"**，不返回运行结果。原因是：

- 任务到点才跑，可能几小时后
- run 的成败只表示"消息有没有送进 agent"，不表示 agent 干得怎么样

所以别对用户说"任务已成功执行"，只能说"任务已创建，下次运行时间 X"。

## 常见错误

| 报错 | 原因 |
|---|---|
| `cron 最小间隔是 5 分钟` | 表达式太密（如 `* * * * *`） |
| `未知时区：…` | 时区拼错，必须是 IANA 名 |
| `一次性任务的时间必须是将来的时刻` | `at` 已经过去了 |
| `sessionMode=new 时不能指定 sessionId` | `new` 模式不接受 `sessionId` |
| `会话不存在` / `会话 … 不属于该 agent` | `reuse` 的绑定目标无效 |

## 先查再建

创建前如果不确定是否已有同名任务，先 `action:"list"` 看一眼，避免重复排程堆叠。
取消用 `action:"cancel"` + `taskId`。
